零活工人工资管理App —— 完整开发需求文档（V1.2 决策版）
============================================================

⚠️ 变更摘要（相对 V1.1）

V1.2 是 V1.1 决策版基础上的**产品模型重构**，根因：
- V1.1 首页是"今日所有记录"流水视图，妈妈难以看清"张姐到底有几笔、付了几笔"
- V1.2 改为"按人组织"：工人列表 → 工人详情 → 账单编辑（三层模型）
- 简化同名查重交互（去二次确认）
- 备注 / 地点字段推迟到 M3（与扫码信息一起加 schema 迁移）

主要变更：

1. **首页模型**：V1.1 是"今日所有记录"流水视图 → V1.2 是"工人列表"卡片视图
2. **视图层级**：V1.1 是 2 层（首页 + 查账页）→ V1.2 是 3 层（工人列表 + 工人详情 + 账单编辑）
3. **同名查重**：V1.1 是"复用 / 新建 + 二次确认" → V1.2 是"切换到该工人 / 改名新建"两个按钮，无二次确认
4. **账单字段**：V1.1 只有日期 + 金额 + 支付状态 → V1.2 增加备注、地点（M3 schema 迁移 1→2 加字段）
5. **添加工人**：V1.1 未明确 → V1.2 明确只在"添加账单"时自动建工人，首页没有独立 [+ 新增工人] 按钮
6. **里程碑切片**：V1.1 的 M1-M5 重新切分为新 M1-M5（结构变了，但工作量大致相当）

数据库表 `workers` 和 `wage_records` 字段在 M1 / M2 不变。V1.2 的 M3 会加 `notes / location` 字段，届时做 schema 迁移 1→2。

文档说明：本文件为 Android 单机应用的需求规格，与 CLAUDE.md v2.2、
DEVELOPMENT_GUIDELINES.md v1.0 配套使用。所有交互逻辑、数据库设计、
非功能需求均已明确，可作为 AI Coding 的输入材料。

------------------------------------------------------------
一、项目概述
------------------------------------------------------------

一句话定位：帮助带班妈妈（保洁零活）通过扫码 / 手动登记每日各工人的出工工资，
按"工人 → 账单"层级管理支付状态，杜绝漏付、错付。

核心价值：

- 扫码即录人，无需提前维护工人库
- 按工人查看其所有账单（未付 / 已付分组）
- 支付状态按"账单"维度独立标记，撤销无副作用
- 自动汇总（每日 / 每人）未付条数和金额
- 数据全在手机本地，无需网络

------------------------------------------------------------
二、目标用户与使用场景
------------------------------------------------------------

用户：50 岁左右带班母亲，手机为华为鸿蒙系统，视力一般，偏好大字体大按钮

场景：

1. 早晨集合时，工人出示微信 / 支付宝收款码，妈妈逐一扫码录入姓名和当
   日工资金额。
2. 收工后，进入某工人的详情页，看他今天有几笔未付，逐张标记已付
   （或先撤销错误的标记，再修改）。
3. 月底需要对账时，按工人筛选，按日期查看所有账单，导出 CSV 文件
   备份。

------------------------------------------------------------
三、核心功能列表（共 5 个模块）
------------------------------------------------------------

3.1 添加账单
- 入口：首页 FAB（右下角浮动按钮）[+] / 工人详情页 FAB [+]
- 扫码：扫描合法二维码 → 自动带出工人姓名 → 录入金额 / 备注 / 地点 → 保存
- 手动：无二维码时手动录入（自动建工人）
- 同名查重：失焦后弹"切换到该工人 / 改名新建"对话框（详见第四章 4.4）

3.2 支付标记
- 入口：工人详情页每张账单卡片上的 [✅ 标记已付] 按钮
- 单张账单独立标记 is_paid=1，写入 paid_time
- 已付账单可撤销（is_paid=0, paid_time=NULL）
- 所有标记 / 撤销 / 删除操作需 AlertDialog 二次确认

3.3 工人详情
- 入口：首页工人卡片点击进入
- 显示某工人的所有账单（按日期倒序，未付 / 已付分组）
- 每张账单可点击进入编辑（M2），可长按弹操作菜单（M2）
- 底部汇总：共 N 笔 / 未付 X 笔 / 已付 Y 笔 / 合计金额

3.4 历史日期 + 工人筛选
- 工人详情页：日期切换（默认今日，可选历史日期）
- 首页：日期过滤（M4 实现，先固定为"今日"）
- 按工人筛选（M4 实现，先省略）

3.5 数据导出 + 清空
- CSV 导出当前筛选条件下的所有账单
- FileProvider 分享至微信 / 文件传输助手
- 清空所有工资记录（两次确认，保留工人档案）

------------------------------------------------------------
四、交互流程详述
------------------------------------------------------------

4.1 工人列表（首页 / 主工作台）

顶部区域：
- 当前日期（格式："2026年8月9日 星期五"），28sp 加粗居中
- 右上角图标 [🔍 筛选]（M4 实现，先省略）

中央列表区：
- 工人卡片列表，每张卡片显示：
  - 工人姓名（22sp 加粗）
  - 未付 X 笔 / ¥XXX.XX（红色）
  - 已付 X 笔 / ¥XXX.XX（绿色）
  - 最近出工日期（灰色小字）
- 首次空状态：显示"还没有工人，点击 [+] 添加第一笔账单"提示

底部 FAB（右下角浮动按钮，60dp）：
- [+] 添加账单

工人卡片交互：
- 点击卡片 → 进入该工人的详情页

添加账单入口（FAB [+]，弹 ModalBottomSheet 半屏）：
- 出工日期（默认今日，可选历史日期；M4 实现日期选择器）
- 金额输入（数字键盘，默认焦点）
- 备注输入（可选，M3 才有字段）
- 地点输入（可选，M3 才有字段）
- [✅ 添加] 按钮（蓝色大按钮）
- [取消] 按钮
- 点击添加：
  - 同名查重（详见 4.4）
  - 写入数据库（Room 事务里写 Worker + WageRecord）
  - 刷新工人列表，Toast 提示"已添加 XXX ¥XXX"

底部统计栏（固定在列表上方，22sp）：
- 🔴 今日未付：X 笔 / ¥XXX.XX
- 🟢 今日已付：X 笔 / ¥XXX.XX
- 每次添加或标记后自动更新

4.2 工人详情（点击工人卡片进入）

顶部导航：
- ← 返回箭头
- 中间标题 "👤 XXX"（工人姓名，22sp 加粗）
- 右上角图标 [📤 导出]（M5 实现）

工人信息卡：
- 工人姓名（24sp）
- 首次登记日期
- 统计行：共 N 笔 / 未付 X 笔 / 已付 Y 笔 / 累计金额

账单列表（按日期倒序，分两组）：
- 未付组（顶部，红色标题 "🔴 未付"）：
  - 每张账单卡片：
    - 日期 + 星期（22sp）
    - 金额（24sp 加粗，红色）
    - 备注 + 地点（M3 才有字段）
    - [✅ 标记已付] 按钮（M2 实现）
  - 点击卡片 → 进入账单编辑（M2 实现）
- 已付组（底部，绿色标题 "🟢 已付"）：
  - 每张账单卡片：
    - 日期 + 星期
    - 金额（绿色）
    - 备注 + 地点（M3 才有字段）
    - 支付时间 HH:mm
  - 长按 → 弹操作菜单 [撤销付款] [删除记录]（M2 实现，二次确认）

底部 FAB：[+] 添加账单（同首页）

底部汇总（M2 实现）：
- 共 N 笔，合计 ¥XXX.XX
- 未付 X 笔 / 已付 Y 笔

4.3 账单编辑（M2 实现，先占位）

顶部导航：
- ← 返回箭头
- 中间标题 "📝 编辑账单" / "📝 查看账单"
- 右上角 [删除] 按钮（二次确认，M2 实现）

表单（编辑模式）：
- 出工日期 [日期选择器，M4 实现]
- 工资金额 [数字输入框]
- 备注 [文本输入，M3 才有字段]
- 地点 [文本输入，M3 才有字段]
- 状态切换：未付 / 已付（已付账单不能改，要改先撤销）

按钮：
- [✅ 保存]（编辑模式）/ [✅ 添加]（新建模式）
- [取消]

4.4 同名查重（V1.2 简化决策）

失焦后查重（= 精确匹配）：
- 0 条同名 → 直接允许 [✅ 添加]（自动建工人 manual_xxx）
- ≥1 条同名 → 弹 AlertDialog：
  - 标题：「XXX」已存在
  - 内容：是否切换到该工人新增一张账单？
  - 按钮 A："切换到该工人"（绿色加粗）→ 用已存在的 worker_id 写账单
  - 按钮 B："改名新建"（红色）→ 关闭弹窗，用户继续改输入框
- **无二次确认**（V1.1 的"确认新建同名？"对话框删除）

业务逻辑：
- 同名字符串不等于同一个人（两个张姐可能不是同一人）
- 用户主动决策（切换 / 改名）而非系统自动复用
- 简化交互步骤，让妈妈不被多次弹窗打扰

六、数据库设计
------------------------------------------------------------

V1.2 M1 / M2 表结构（schema version = 1，与 V1.1 一致）：

表 1：workers（工人表）

| 字段            | 类型     | 说明                                       |
|-----------------|----------|--------------------------------------------|
| id              | TEXT PK  | 白名单 worker_id 或 manual_xxx             |
| name            | TEXT NN  | 工人姓名                                   |
| qr_raw          | TEXT     | 原始二维码内容（M3 用，可空）              |
| qrcode_path     | TEXT     | 收款码图片本地路径（M3 用，可空）          |
| is_manual       | INT NN=0 | 0=扫码，1=手动                              |
| first_work_date | TEXT     | 首次登记日期（yyyy-MM-dd）                  |

索引：INDEX(name)

表 2：wage_records（账单表）

| 字段         | 类型           | 说明                                  |
|--------------|----------------|---------------------------------------|
| id           | INT PK AUTO    | 自增主键                              |
| worker_id    | TEXT NN        | 关联 workers.id（不强制 FK CASCADE）  |
| work_date    | TEXT NN        | 出工日期（yyyy-MM-dd）                |
| wage_cent    | INTEGER NN     | 工资金额（单位"分"，避免浮点误差）    |
| is_paid      | INTEGER NN=0   | 0=未付，1=已付                        |
| paid_time    | TEXT           | 支付时间 yyyy-MM-dd HH:mm:ss（NULL） |
| create_time  | TEXT NN        | 记录创建时间 yyyy-MM-dd HH:mm:ss      |

索引：INDEX(worker_id), INDEX(work_date), INDEX(is_paid)

约束：
- wage_cent > 0
- work_date ≤ 今天（不允许未来）
- V1 不开 ON DELETE CASCADE，删除一致性由应用层维护

M3 schema 迁移（1 → 2）：新增字段
- wage_records.notes (TEXT NULL) —— 备注
- wage_records.location (TEXT NULL) —— 地点

迁移策略：Room Migration 对象 + Migration 回调，不清数据。

------------------------------------------------------------
第七章 二维码识别口径（V1 强制规则）
------------------------------------------------------------

本章与 V1.1 第七章一致，本节仅概要：

7.1 严格白名单（仅这三类可作 worker_id）

| 类型           | 正则                                                      |
|----------------|-----------------------------------------------------------|
| 微信好友码     | ^https://u\.wechat\.com/[A-Za-z0-9_-]{20,30}$              |
| 支付宝收款码   | ^https://qr\.alipay\.com/[A-Za-z0-9]+$                    |
| 微信个人收款码 | ^wxp://.+                                                  |

处理：
- 查 workers 表，若已存在同 id → 自动填充姓名
- 若不存在 → BottomSheet 中姓名留空

7.2 拒绝并提示（不入表，不存图）

| 类型           | 正则                                  | 提示文案                          |
|----------------|---------------------------------------|-----------------------------------|
| 微信付款码     | ^1[0-5]\d{16}$                        | "这是付款码，请出示收款码"        |
| 支付宝付款码   | ^2[5-9]\d{14,22}$\|^30\d{14,22}$      | "这是付款码，请出示收款码"        |
| 微信商户码     | ^weixin://wxpay/                      | "这是订单码，请出示收款码"        |

7.3 未识别内容

- Toast "无法识别，是否手动录入？"
- 点击手动录入 → 走 4.1 节添加账单流程

7.4 ML Kit 配置

- BarcodeFormat = QR_CODE
- 启用所有方向识别
- 不启用 EAN / UPC 等条码格式

7.5 图片存储策略（M3）

- 文件名：SHA-256(qr_raw).jpg（十六进制小写）
- 路径：context.filesDir.absolutePath + "/qrcodes/" + 文件名
- 存图失败不阻断记账

7.6 权限降级（M3）

- 相机被永久拒绝 → 引导跳系统设置
- 手动录入路径始终可用

八、非功能性需求
------------------------------------------------------------

- UI 风格：大字体（≥20sp），大按钮（≥60dp），高对比度（白底黑字 + 红绿蓝三色）
- 颜色全部放入 colors.xml，支持 night 资源（夜间模式暂保持高对比度）
- 交互反馈：所有点击需有视觉反馈（按钮颜色变化、Toast 提示）
- 防误触：所有删除操作必须二次确认；清空所有工资记录需两次确认
- 性能：支持最多 200 名工人、5000 条工资账单，查询响应时间 < 1 秒
- 数据安全：无网络权限，所有数据仅存于手机本地
- 无障碍：ImageButton 必须设 contentDescription，touch target ≥ 48dp
- 国际化：日期显示用 DateTimeFormatter + Locale.CHINA，不硬编码"年月日星期"

九、开发注意事项
------------------------------------------------------------

9.1 同名查重（V1.2 简化版）

失焦后查重（= 精确匹配）：
- 0 同名 → 自动建工人（manual_xxx UUID 前缀），允许提交
- ≥1 同名 → 弹"切换到该工人 / 改名新建"对话框
  - 切换：用已存在 worker_id 写账单
  - 改名：关闭弹窗，用户继续改输入框
- 无二次确认
- 不允许"复用"概念（同名字符串可能不是同一个人）

业务规则放 `util/PaymentRules.java`：
- MARK_PAID / REVOKE_PAYMENT / EDIT / DELETE 的合法性校验
- 时间格式化（HH:mm 显示）

9.2 备注 / 地点字段（M3 一起加）

- 数据库 schema 迁移 1 → 2
- Migration 文件加 `notes / location` 字段（均可空）
- M1 / M2 UI 占位（输入框可输入但不存数据库）

9.3 ML Kit / 图片（M3）

- ML Kit 模型首次启动会初始化，需 ~50ms 异步预热
- Bitmap 压缩 80% JPEG 放 Dispatchers.IO 子线程
- Compose 中显示图片用 AsyncImage（Coil 库）
- 图片加载失败降级：Coil 的 fallback(R.drawable.ic_no_image)

9.4 CSV 导出 / 清空（M5）

- UTF-8 BOM（写入文件首三个字节 EF BB BF）
- 字段含逗号 / 换行 / 引号时按 RFC4180 转义
- 行尾 \r\n
- 金额统一保留两位小数显示
- FileProvider authority：${applicationId}.fileprovider
- xml/file_paths.xml 配置 cache-path exports/

9.5 ProGuard / R8（release 包）

keep 规则：
- com.google.mlkit.** { *; }
- androidx.room.** { *; }
- com.example.wagemanager.data.** { *; }

9.6 coreLibraryDesugaring

- build.gradle 加 coreLibraryDesugaring 'com.android.tools:desugar_jdk_libs:2.0.4'
- compileOptions { isCoreLibraryDesugaringEnabled = true }
- 业务代码统一使用 java.time.LocalDate / LocalDateTime

十、V1 强制结论清单（V1.2 更新版）
------------------------------------------------------------

1. [首页] 工人列表，按人组织账单
2. [视图层级] 工人列表 → 工人详情 → 账单编辑（三层）
3. [账单字段] 日期 + 金额 + 支付状态（M1/M2）；M3 加备注 / 地点
4. [添加工人] 仅在"添加账单"时自动建，首页无独立 [+ 新增工人]
5. [同名查重] 弹"切换到该工人 / 改名新建"，无二次确认
6. [支付最小单元] 单张账单独立判断支付状态
7. [已付撤回] 已付账单可撤销（is_paid=0, paid_time=NULL）
8. [删除] 工资账单单删；"清空"只清 wage_records；工人档案保留
9. [日期] LocalDate / LocalDateTime；仅允许补录 ≤ 今天
10. [图片命名] SHA-256(qr_raw).jpg；存图失败不阻断（M3）
11. [导出] UTF-8 BOM + RFC4180 + 文件名带日期+工人（M5）
12. [权限] 手动录入永远可用，与相机权限独立（M3）
