零活工人工资管理App —— 完整开发需求文档（V1.1 决策版）
============================================================

⚠️ 变更摘要（相对 V1.0）

- 技术栈已从 V1.0 的 Java + ZXing + XML/RecyclerView 切换为：
  Kotlin 1.9.10 + Jetpack Compose + Room + ML Kit（离线版）。
  与 CLAUDE.md v2.0 (2026-08-02) 保持一致。
- 数据库 wage 字段由 REAL 改为 INTEGER（单位：分），规避浮点误差。
- 数据库新增 qr_raw、is_manual 字段；增加索引。
- 增加"二维码识别口径"独立章节（第七章），强制严格白名单 A 模式。
- 增加"撤销已付款"操作；已付/未付均可长按删除。
- 增加"手动录入同名复用"决策树。
- 重复登记：同一 worker 同一天允许多条记录；首页按记录数统计。
- 图片命名改为 SHA-256(qr_raw).jpg，原始内容与图片双轨存储。
- 权限拒绝时引导跳系统设置；手动录入路径不依赖相机权限。
- CSV 强制 UTF-8 BOM + RFC4180 转义；文件名带工人姓名。
- 排期从 5 天调整为 7 天，预留真机测试。

文档说明：本文件为 Android 单机应用的需求规格，与 CLAUDE.md v2.0、
DEVELOPMENT_GUIDELINES.md v1.0 配套使用。所有交互逻辑、数据库设计、
非功能需求均已明确，可作为 AI Coding 的输入材料。

------------------------------------------------------------
一、项目概述
------------------------------------------------------------

一句话定位：帮助带班妈妈（保洁零活）通过扫码快速登记当日出工人员及
浮动工资，并标记支付状态，杜绝漏付、错付。

核心价值：

- 扫码即录人，无需提前维护工人库
- 自动汇总今日工资总额及未付/已付条数
- 支持手动录入与扫码混合场景
- 数据全在手机本地，无需网络

------------------------------------------------------------
二、目标用户与使用场景
------------------------------------------------------------

用户：50 岁左右带班母亲，手机为华为鸿蒙系统，视力一般，偏好大字体大按钮

场景：

1. 早晨集合时，工人出示微信/支付宝收款码，妈妈逐一扫码录入姓名和
   当日工资金额。
2. 收工后，查看未付名单，对照收款码图片手动微信转账，并在 App 内
   标记已付；如误标可撤销。
3. 月底或需要对账时，按日期或工人查询历史记录，并导出 CSV 文件备份。

------------------------------------------------------------
三、核心功能列表（共 4 个模块）
------------------------------------------------------------

3.1 扫码登记
- 扫描收款码，按白名单规则判断是否可登记
- 收款码匹配到的工人自动带出姓名
- 输入当日工资（分，最小单位 1 分）
- 保存收款码图片至本地（SHA-256 命名）
- 支持手动录入（无二维码时）

3.2 支付标记
- 首页双标签（未付/已付）列表
- 点击未付项弹窗显示收款码图片 + "标记已付"按钮
- 已付列表显示支付时间
- 已付项支持"撤销付款"（恢复未付）

3.3 历史查账
- 按日期切换查看记录
- 按工人姓名筛选
- 显示汇总小计
- 支持删除单条记录（不影响工人信息）

3.4 数据导出
- 生成 CSV 文件，通过系统分享发送至微信/文件传输助手
- 提供"清空所有工资记录"危险操作（二次确认，保留工人档案）

------------------------------------------------------------
四、交互流程详述
------------------------------------------------------------

4.1 首页（主工作台）

顶部区域：
- 显示当前日期（格式：2026年8月7日 星期五），28sp 加粗居中
- 右上角图标 "📊 查账"，点击进入查账页

中央扫码区：
- 蓝色大按钮（宽 85%，高 120dp）："📷 扫码登记工人"
- 点击 → 启动 ML Kit ScannerActivity
- 扫码成功后按第七章规则分支处理：
  * 白名单命中 → 弹 BottomSheet 输入姓名 + 工资
  * 付款码/商户码 → Toast 提示并返回首页，不弹窗
  * 未识别内容 → Toast "无法识别，是否手动录入？"
- 弹 BottomSheet 半屏：
  * 提示"已识别收款码"
  * 工人姓名输入框（已存在则自动填充）
  * 今日工资输入框（数字键盘，默认焦点）
  * 确认按钮 "✅ 登记"
  * 取消按钮
- 点击确认：
  * 写入 workers 表（已存在则只更新 name）
  * 插入一条 wage_records（work_date=今日, wage_cent=输入值, is_paid=0）
  * 刷新底部未付列表，Toast 提示"已登记：XXX 280元"

- 扫码按钮正下方：灰色链接 "✏️ 扫码失败？手动录入"
- 点击 → 弹同样的 BottomSheet（无 worker_id）
- 姓名输入框失焦后查重：
  * 0 匹配 → 直接登记（manual_ 前缀 worker_id）
  * 1 匹配 → 自动填充
  * ≥2 匹配 → 弹列表 [复用该工人] [新建工人]
- manual_ 工人不保存图片

统计汇总栏（固定于扫码区下方，24sp 加粗三行）：
- 💰 今日合计：0.00 元
- 🔴 未付：0 条
- 🟢 已付：0 条
- 每次登记或标记后自动更新

底部双标签列表：
- 标签栏：两个按钮并排
  * 左："未付（X）"，选中 #F44336 红，未选灰
  * 右："已付（X）"，选中 #4CAF50 绿，未选灰
  * 默认未付
- 未付列表：
  * 每项：👤 姓名 金额XX.XX元 [✅ 标记已付]
  * 点击卡片主体 → 弹窗显示收款码图（无图显示占位 + "无收款码图片，请手动转账"）
  * 点击 [标记已付] → AlertDialog 确认 → is_paid=1, paid_time=now → 刷新
- 已付列表：
  * 每项：👤 姓名 金额XX.XX元  支付时间 HH:mm
  * 长按 → 操作菜单 [撤销付款] [删除记录]
  * 撤销 → is_paid=0, paid_time=NULL
  * 删除 → AlertDialog 确认
- 空列表提示文字（区分未付/已付）

4.2 查账页（右上角查账进入）

顶部导航：
- ← 返回箭头
- 中间标题 "📊 工资记录"

筛选区域：
- 日期切换："← 前一天" 与 "后一天 →"，中间显示当前选中日期（默认今日）
  * 长按日期 → 日期选择器
  * 未来日期按钮禁用
  * 可回退到任意过去日期
- 工人筛选：Spinner，默认"全部工人"，选项来自所有已登记工人姓名
  * 同名工人用 (worker_id后4位) 区分显示

汇总小计：
- "共 X 条记录，合计 XXXX.XX 元，未付 X 条，已付 X 条"
- 灰色背景，20sp

记录列表：
- 每项：姓名、金额、日期、状态、支付时间（若有）
- 点击无操作；长按 → 操作菜单 [撤销付款]（仅已付） [删除记录]

底部操作栏：
- "📤 导出 CSV" 按钮
  * 生成当前筛选条件下的所有记录
  * 文件名：工资记录_{yyyyMMdd}_{全部|姓名}.csv
  * UTF-8 BOM + RFC4180 转义 + \r\n 换行
  * 列：日期,工人ID,工人姓名,工资金额,支付状态,支付时间,记录创建时间
  * FileProvider 分享，可选微信发送
- "🗑️ 清空所有工资记录" 按钮（红色）
  * 两次确认 → 仅删 wage_records 与已被孤立引用的图片
  * 提示：保留工人档案，仅清工资

五、技术选型（与 CLAUDE.md v2.0 同步）
------------------------------------------------------------

- 开发语言：Kotlin 1.9.10
- IDE：Android Studio（云端 CI 用 GitHub Actions）

- 最低 SDK：Android 7.0 (API 24)
- target SDK：34
- 网络权限：无（纯本地应用）
- desugaring：开启 coreLibraryDesugaring，使用 java.time API

------------------------------------------------------------
六、数据库设计（两张表）
------------------------------------------------------------

表1：workers（工人表）

| 字段            | 类型     | 说明                                       |
|-----------------|----------|--------------------------------------------|
| id              | TEXT PK  | 白名单 worker_id 或 manual_xxx             |
| name            | TEXT NN  | 工人姓名                                   |
| qr_raw          | TEXT     | 原始二维码内容（白名单成功后存，可空）      |
| qrcode_path     | TEXT     | 收款码图片本地路径（可空，manual_ 为空）    |
| is_manual       | INT NN=0 | 0=扫码，1=手动                              |
| first_work_date | TEXT     | 首次登记日期（yyyy-MM-dd）                  |

索引：INDEX(name)

表2：wage_records（工资记录表）

| 字段         | 类型           | 说明                                  |
|--------------|----------------|---------------------------------------|
| id           | INT PK AUTO    | 自增主键                              |
| worker_id    | TEXT NN        | 关联 workers.id（不强制 FK CASCADE）  |
| work_date    | TEXT NN        | 出工日期（yyyy-MM-dd）                |
| wage_cent    | INTEGER NN     | 工资金额（单位：分，避免浮点误差）    |
| is_paid      | INTEGER NN=0   | 0=未付，1=已付                        |
| paid_time    | TEXT           | 支付时间 yyyy-MM-dd HH:mm:ss（NULL） |
| create_time  | TEXT NN        | 记录创建时间 yyyy-MM-dd HH:mm:ss      |

索引：INDEX(worker_id), INDEX(work_date), INDEX(is_paid)

约束：
- wage_cent > 0
- work_date ≤ 今天（不允许未来）
- V1 不开 ON DELETE CASCADE，删除一致性由应用层维护

------------------------------------------------------------
第七章 二维码识别口径（V1 强制规则）
------------------------------------------------------------

本章是 V1.1 新增的强制章节，所有扫码分支逻辑以此为准。

7.1 严格白名单（仅这三类可作 worker_id）

| 类型           | 正则                                                      | 来源           |
|----------------|-----------------------------------------------------------|----------------|
| 微信好友码     | ^https://u\.wechat\.com/[A-Za-z0-9_-]{20,30}$              | 微信加好友     |
| 支付宝收款码   | ^https://qr\.alipay\.com/[A-Za-z0-9]+$                    | 支付宝当面付   |
| 微信个人收款码 | ^wxp://.+                                                  | 微信收款（非官方稳定） |

处理：
- 查 workers 表，若已存在同 id → 自动填充姓名
- 若不存在 → BottomSheet 中姓名留空

7.2 拒绝并提示（不入表，不存图）

| 类型           | 正则                                  | 提示文案                          |
|----------------|---------------------------------------|-----------------------------------|
| 微信付款码     | ^1[0-5]\d{16}$                        | "这是付款码，请出示收款码"        |
| 支付宝付款码   | ^2[5-9]\d{14,22}$\|^30\d{14,22}$      | "这是付款码，请出示收款码"        |
| 微信商户码     | ^weixin://wxpay/                      | "这是订单码，请出示收款码"        |

7.3 未识别内容

- 既不在白名单也不在拒绝列表 → Toast "无法识别，是否手动录入？"
- 点击手动录入 → 走 4.1 节手动录入流程

7.4 ML Kit 配置（写死）

- BarcodeFormat = QR_CODE
- 启用所有方向识别（rotation 0/90/180/270）
- 不启用 EAN/UPC 等条码格式
- 解码线程默认（ML Kit 内部已用 Executor）

7.5 图片存储策略

- 文件名：SHA-256(qr_raw).jpg（十六进制小写，64 字符）
- 路径：context.filesDir.absolutePath + "/qrcodes/" + 文件名
- 数据库同时存 qr_raw（原始文本）与 qrcode_path（本地路径）
- 存图失败不阻断登记，qrcode_path 留空
- 用户取消登记 → 删除临时图片
- 删除最后一条工资记录 → 删除该图片
- 加载图片时若 BitmapFactory.decodeFile 返回 null → 显示占位图

7.6 权限降级

- 相机被永久拒绝 → Intent(Settings.ACTION_APPLICATION_DETAILS_SETTINGS)
- 相机被临时拒绝 → Toast 后返回首页
- 手动录入路径必须始终可用，与相机权限完全独立

------------------------------------------------------------
八、非功能性需求
------------------------------------------------------------

- UI 风格：大字体（≥20sp），大按钮（≥60dp），高对比度（白底黑字 + 红绿蓝三色）
- 颜色全部放入 colors.xml，支持 night 资源
- 交互反馈：所有点击需有视觉反馈（按钮颜色变化、Toast 提示）
- 防误触：所有删除操作必须二次确认；清空所有工资记录需两次确认
- 性能：支持最多 200 名工人、5000 条工资记录，查询响应时间 < 1 秒
- 数据安全：无网络权限，所有数据仅存于手机本地，导出文件需用户手动分享
- 无障碍：ImageButton 必须设 contentDescription，touch target ≥ 48dp
- 国际化：日期显示用 DateTimeFormatter + Locale.CHINA，不硬编码"年月日星期"

------------------------------------------------------------
九、开发注意事项
------------------------------------------------------------

9.1 扫码与图片

- ML Kit 模型首次启动会初始化，需 ~50ms 异步预热
- Bitmap 压缩 80% JPEG 放 Dispatchers.IO 子线程
- Compose 中显示图片用 AsyncImage（Coil 库）
- 图片加载失败降级：Coil 的 fallback(R.drawable.ic_no_image)

9.2 手动录入同名复用

- 失焦后查 SELECT id FROM workers WHERE name = ?
- 0/1/≥2 匹配按 4.1 节规则处理
- 用户选 [新建工人] 时强制弹确认（避免误重名）

9.3 撤销付款

- 仅 is_paid=1 的记录可撤销
- 撤销后 is_paid=0, paid_time=NULL
- 不写审计日志（V1）

9.4 补录日期

- work_date ≤ today
- 不允许未来日期，按钮置灰
- 历史页可补录任意过去日期

9.5 CSV 导出

- UTF-8 BOM（写入文件首三个字节 EF BB BF）
- 字段含逗号/换行/引号时按 RFC4180 转义（外加双引号，内部双引号 → "")
- 行尾 \r\n
- 金额统一保留两位小数显示
- FileProvider authority：${applicationId}.fileprovider
- xml/file_paths.xml 配置 cache-path exports/

9.6 ProGuard / R8

- release 包加 keep 规则：
  - com.google.mlkit.** { *; }
  - androidx.room.** { *; }
  - com.example.wagemanager.data.** { *; }

9.7 coreLibraryDesugaring

- build.gradle 加 coreLibraryDesugaring 'com.android.tools:desugar_jdk_libs:2.0.4'
- compileOptions { isCoreLibraryDesugaringEnabled = true }
- 业务代码统一使用 java.time.LocalDate / LocalDateTime

9.8 FileProvider 配置

- AndroidManifest.xml 注册 provider
- authorities：${applicationId}.fileprovider
- exported=false, grantUriPermissions=true
- meta-data 指向 @xml/file_paths

------------------------------------------------------------
十、V1 强制结论清单（开发前必须确认）
------------------------------------------------------------

1. [二维码] 仅白名单三类入 worker_id；付款码/红包码/商户码拒绝并提示。
2. [重复登记] 同一 worker 同一 work_date 允许多条；首页显示当日合计。
3. [金额] 存储 INTEGER 分；输入必须 > 0，最多两位小数。
4. [修改] 未付款可编辑姓名/工资；已付款不可改，仅可"撤销付款"。
5. [已付撤回] 已付款长按 → 撤销（is_paid=0, paid_time=NULL）。
6. [手动录入同名] 输入姓名后查重 → 弹窗让用户选"复用 / 新建"。
7. [统计口径] 按记录数统计，注明"条数"而非"人数"。
8. [删除] 工资记录单删；"清空"只清 wage_records；工人档案保留。
9. [日期] LocalDate / LocalDateTime；仅允许补录 ≤ 今天，不允许未来。
10. [图片命名] SHA-256(qr_raw).jpg；存图失败不阻断登记。
11. [导出] UTF-8 BOM，RFC4180 转义，文件名带日期+工人。
12. [权限] 相机被永久拒绝时，引导跳系统设置；手动录入永远可用。
