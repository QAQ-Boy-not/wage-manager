零活工人工资管理App —— 完整开发需求文档（V1.3 决策版）
============================================================

⚠️ 变更摘要（相对 V1.2）

V1.3 是 V1.2 决策版基础上的**核心场景重构**，根因：
- V1.2 只建模"角色 + 订单"两层，缺了"工区"这个核心场景实体
- 实际使用场景是"某人在某工地干活给多少钱"，工区是不可少的
- 同名处理在 UI 上仍有"切换/改名"对话框，过于复杂

主要变更（V1.3 决策版）：

1. **新增 Worksite（工区）实体**（V1.3 关键变更）：
   - 表达"在哪干活"（小区 / 单元 / 楼层 / 房间）
   - 三实体关系：Worker 1—N WageRecord N—1 Worksite

2. **首页重构**：从"工人列表 + 加账单 FAB"改为"按工人聚合的今日订单"：
   - 工人卡片：未付笔数 / 总金额 + 订单缩略
   - 点开看该工人今日订单详情
   - FAB 批量添加（多选工人 + 共享工区/金额/备注）

3. **批量添加订单**：
   - 一次提交为多个工人创建订单
   - 共享工区 + 金额 + 备注 + 日期
   - 工人选择器：弹出式 Dialog（不是 BottomSheet，避免嵌套限制）+ 搜索框

4. **同名处理简化**（V1.2 → V1.3）：
   - 去掉"切换/改名"对话框
   - 输入失焦 → 有同名 → 输入框标红 + 错误"已存在「X」，请改名"
   - 强制妈妈改名字才能提交
   - 保证数据库里同名字符串全局唯一

5. **长按工人项查看详情**（高级功能）：
   - 弹 Dialog 显示该工人累计统计
   - 不影响主流程

6. **去掉长按**（M2.1 反馈）：
   - 老年用户（50 岁带班妈妈）很难发现长按操作
   - 替换为右上角 "⋮" 图标按钮 + Dialog 操作菜单
   - 如果非用长按不可，必须有提示文字

⚠️ 变更摘要（M2.1 增量，相对上面 V1.3 决策版）

M2.1 落地过程中根据用户实测反馈调整了 4 项：

1. **页面正式命名**（M2.1）：
   - 首页 → **工人列表**（顶部加"📋 工人列表"）
   - 详情页 → **账单详情**（顶部加"📋 账单详情"，副标题显示工人名）

2. **批量添加表单加新建入口**（M2.1 Bug16/17）：
   - WorksiteSelector 加 "+ 新建工区" → 弹 CreateWorksiteDialog（名称+地址）
   - WorkerPickerDialog 加 "+ 新建工人" → 弹 CreateWorkerDialog
   - 新建后自动选中/勾选

3. **账单详情改 Tab 切换**（M2.1 Bug19）：
   - 去掉"未付 / 已付"上下分组
   - 顶部两个 Pill 按钮（"🔴 未付（N 笔 / Y 元）" / "🟢 已付（N 笔 / Y 元）"）
   - 列表只显示当前 tab 的账单

4. **"全部标记已付"移到详情页**（M2.1 反馈）：
   - 首页不放（"全部"操作不该在概览层级）
   - 在某工人详情页底部加 ✅ 全部标记已付（仅操作该工人）+ ↩️ 全部撤销
   - 无账可操作时按钮 disable

5. **同名处理：UI 提示而非 Dialog**（M2.1 落地）：
   - 之前 V1.3 决策是"输入失焦 + 输入框标红"
   - 但实际落地时，详情页 +/- 等场景不应触发同名检查
   - RegisterBillSheet 永远 disable 名字输入（详情页上下文），调 addBillToWorker
   - 批量添加场景下，选工人来自数据库（不可能同名），新建工人走 Repository.insertWorker 强制改名

6. **详情页 +/- 走不同后端路径**（M2.1 Bug14）：
   - RegisterBillSheet 新增 `workerId` 参数
   - 详情页 +/-（editingBill=null）：调 repository.addBillToWorker(workerId, ...)，跳过同名检查
   - 编辑模式（editingBill != null）：调 repository.updateWage
   - 批量添加场景：选工人后调 repository.registerBill，强制改名


6. **去掉所有内部 ID 暴露**：
   - UUID 只在系统内部使用
   - UI 只显示工人姓名 + 首次登记日期

7. **数据库 schema 迁移 1→2**：
   - 新增 `worksites` 表
   - `wage_records` 加 `worksite_id`（可空）+ `notes`（可空）

------------------------------------------------------------
一、项目概述
------------------------------------------------------------

一句话定位：帮助带班妈妈（保洁零活）按"角色（工人）→ 订单 → 工区"
三层实体管理每日出工工资，扫码或手动添加订单，逐张标记支付状态，
杜绝漏付、错付。

核心价值：

- 三实体模型贴合现实场景："谁（角色）在哪（工区）干了啥（订单）"
- 批量添加效率高：一次给一群人登记同一笔工资
- 同名字符串全局唯一：避免歧义
- 数据全在手机本地，无需网络

------------------------------------------------------------
二、目标用户与使用场景
------------------------------------------------------------

用户：50 岁左右带班母亲，手机为华为鸿蒙系统，视力一般，偏好大字体大按钮

核心场景：

> "某年某月某日，张三（角色），因为帮我在 xx小区 xx单元 xx楼层 xx号房间
> （工区）进行 xx 劳动（订单备注），我需要支付张三 xxx 元（订单金额），
> 这个支付完成/未完成（订单状态）"

场景：

1. 早晨集合时，妈妈打开 App 看到今日未付订单（按工人聚合）
2. 点 [+] → 选工区 + 金额 + 备注 + 勾选工人 → 一次批量登记
3. 收工后，进入某工人详情看所有订单，标已付 / 撤销 / 删除
4. 月底对账时，进入管理页查看三实体的完整列表

三、核心功能列表（共 3 实体 CRUD + 核心交互）
------------------------------------------------------------

3.1 三实体 CRUD

| 实体 | 字段 | CRUD 入口 |
|------|------|----------|
| **Worker（角色）** | id, name, first_work_date, is_manual, qr_raw(M3), qrcode_path(M3) | 管理页 → 工人 Tab |
| **WageRecord（订单）** | id, worker_id, worksite_id, work_date, wage_cent, notes, is_paid, paid_time, create_time | 首页 FAB 批量添加 / 工人详情页单笔添加 / 工人详情页编辑 |
| **Worksite（工区）** | id, name, address, created_at | 管理页 → 工区 Tab / 订单表单下拉新建 |

3.2 首页（按工人聚合）

- 顶部：今日日期
- 汇总：未付 X 笔 / ¥XXX、已付 X 笔 / ¥XXX
- Tab 切换：未付 / 已付
- 工人卡片列表（按工人聚合）：
  - 姓名 / 应付金额 / 笔数 / 订单缩略（前 2-3 笔）
  - 点击 → 展开该工人的今日订单列表（按工区分组）
  - 长按 → 弹 Dialog 显示工人累计统计
- FAB ➕：批量添加订单

3.3 批量添加订单

- 工区下拉（必填）+ "+ 新建工区" 快捷入口
- 每人金额（必填）
- 备注（可选，所有订单共用）
- 选择工人（点击 → 弹出 WorkerPickerDialog）
- 工人选择器（弹出 Dialog）：
  - 顶部搜索框（按姓名 contains）
  - 已选置顶
  - 全选 / 全不选
- 提交：调用 `repository.registerBills(workerIds, ...)`，事务里循环 INSERT

3.4 工人详情页

- 顶部：← 返回 + 工人姓名
- 工人信息卡：姓名 + 首次登记日期 + 汇总（分行显示）
- 账单列表（按日期倒序，未付 / 已付分组）：
  - 未付账单：日期 + 金额 + [✅ 标记已付] 按钮
  - 已付账单：日期 + 金额 + 支付时间
  - 长按弹操作菜单（标记已付 / 撤销付款 / 删除记录 / 编辑）
- FAB ➕：单笔添加订单（预填工人姓名）

3.5 单笔添加 / 编辑订单（工人详情页 [+ 订单]）

- 工人姓名（预填，不可改）
- 工区下拉
- 金额输入
- 备注输入
- 日期（M4 加日期选择器）

3.6 同名处理（强制改名）

- 输入框失焦 → 查 `findWorkersByExactName`
- 0 同名 → 正常
- ≥1 同名 → 输入框标红 + 提示文字"已存在「X」，请改名（如 张姐A / 张姐(早班)）"
- 提交按钮禁用，必须改名才能提交
- **不弹任何对话框**，完全在输入框层反馈

3.7 支付状态流转

- 标记已付：未付 → 已付 + paid_time=now（详情页未付账单点按钮）
- 撤销付款：已付 → 未付 + paid_time=NULL（详情页已付账单长按菜单）
- 删除记录：任何状态可删（详情页长按菜单）
- 编辑：仅未付可改（已付需先撤销）

3.8 数据导出（M5，本里程碑不做）

六、数据库设计（Schema 2，迁移 1→2）
------------------------------------------------------------

表 1：workers（V1.1 不变）

| 字段            | 类型     | 说明                                       |
|-----------------|----------|--------------------------------------------|
| id              | TEXT PK  | 白名单 worker_id 或 manual_<uuid>          |
| name            | TEXT NN  | 工人姓名（全局唯一）                       |
| qr_raw          | TEXT     | 原始二维码内容（M3 用，可空）              |
| qrcode_path     | TEXT     | 收款码图片本地路径（M3 用，可空）          |
| is_manual       | INT NN=0 | 0=扫码，1=手动                              |
| first_work_date | TEXT     | 首次登记日期（yyyy-MM-dd）                  |

索引：INDEX(name)

表 2：worksites（V1.3 新增）

| 字段       | 类型     | 说明                            |
|------------|----------|---------------------------------|
| id         | TEXT PK  | manual_<uuid>                  |
| name       | TEXT NN  | 工区简称（如"望京 SOHO T3"）   |
| address    | TEXT NN  | 详细地址                        |
| created_at | TEXT NN  | 创建时间 yyyy-MM-dd HH:mm:ss   |

索引：INDEX(name)

表 3：wage_records（V1.1 + V1.3 新增字段）

| 字段         | 类型           | 说明                                       |
|--------------|----------------|--------------------------------------------|
| id           | INT PK AUTO    | 自增主键                                   |
| worker_id    | TEXT NN        | 关联 workers.id（FK NO_ACTION）            |
| **worksite_id** | **TEXT NULL** | **关联 worksites.id（V1.3 新增，可空）**   |
| work_date    | TEXT NN        | 出工日期（yyyy-MM-dd）                     |
| wage_cent    | INTEGER NN     | 工资金额（分）                             |
| **notes**       | **TEXT NULL** | **劳动内容备注（V1.3 新增）**              |
| is_paid      | INTEGER NN=0   | 0=未付，1=已付                             |
| paid_time    | TEXT           | 支付时间（NULL = 未付）                    |
| create_time  | TEXT NN        | 记录创建时间                               |

索引：INDEX(worker_id), INDEX(worksite_id), INDEX(work_date), INDEX(is_paid)

约束：
- wage_cent > 0（SQLite 触发器兜底）
- work_date ≤ 今天（SQLite 触发器兜底）
- V1 不开 ON DELETE CASCADE

Schema 迁移 1→2：
```kotlin
val MIGRATION_1_2 = object : Migration(1, 2) {
    override fun migrate(database: SupportSQLiteDatabase) {
        // 1. 新增 worksites 表
        database.execSQL("""
            CREATE TABLE worksites (
                id TEXT NOT NULL PRIMARY KEY,
                name TEXT NOT NULL,
                address TEXT NOT NULL,
                created_at TEXT NOT NULL
            )
        """.trimIndent())
        database.execSQL("CREATE INDEX index_worksites_name ON worksites(name)")

        // 2. wage_records 加 worksite_id 列
        database.execSQL("ALTER TABLE wage_records ADD COLUMN worksite_id TEXT")
        database.execSQL("CREATE INDEX index_wage_records_worksite_id ON wage_records(worksite_id)")

        // 3. wage_records 加 notes 列
        database.execSQL("ALTER TABLE wage_records ADD COLUMN notes TEXT")
    }
}
```

九、开发注意事项
------------------------------------------------------------

9.1 同名处理（V1.3 强制改名）

- 输入框失焦 → `findWorkersByExactName(name)`
- 0 同名 → 无反馈
- ≥1 同名 → 输入框标红 + 错误文字"已存在「X」，请改名"
- 提交按钮禁用（`enabled = !hasNameError`）
- **不弹任何对话框**，UI 极简

业务原因：
- 同名字符串 = 同一个人（无歧义）
- 数据库里全局唯一，妈妈必须主动起区分名（张姐A / 张姐(早班)）

9.2 内部 ID 不暴露给用户

- UUID / worker_id 仅在系统内部使用
- UI 列表项只显示 👤 + 姓名 + 首次登记日期（不显示 id 后 4 位）
- 调试 / 长按详情 Dialog 也不显示完整 UUID

9.3 工人选择器用 Dialog 而非 BottomSheet

- 原因：ModalBottomSheet 不支持嵌套（批量表单里嵌选择器）
- 解决：用 Material Dialog（可自定义内容），支持任意嵌套

9.4 批量添加订单的事务

- `registerBills(workerIds, worksiteId, wageCent, notes, workDate)`
- 事务里循环 INSERT，失败回滚

9.5 三实体 CRUD
