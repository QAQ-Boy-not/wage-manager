零活工人工资管理App —— 完整开发需求文档（V1.0）
===============================================

文档说明：本文档为纯本地Android应用的需求规格说明，适用于Java程序员直接上手开发。所有交互逻辑、数据库设计、非功能需求均已明确，可作为AI Coding的输入材料。

一、项目概述

一句话定位：帮助带班妈妈（保洁零活）通过扫码快速登记当日出工人员及浮动工资，并标记支付状态，杜绝漏付、错付。

核心价值：

扫码即录人，无需提前维护工人库

自动汇总今日工资总额及未付/已付人数

支持固定工人与临时工混合场景

数据全在手机本地，无需网络

二、目标用户与使用场景

用户：50岁左右带班母亲，手机为华为鸿蒙系统，视力一般，偏好大字体大按钮

场景：

早晨集合时，工人出示微信/支付宝收款码，妈妈逐一扫码录入姓名和当日工资金额

收工后，查看未付名单，对照收款码图片手动微信转账，并在App内标记已付

月底或需要对账时，按日期或工人查询历史记录，并导出CSV文件备份

三、核心功能列表（共4个模块）

扫码登记

扫描收款码，自动识别ID

若新工人则手动输入姓名，若已存在则自动带出

输入当日工资

保存收款码图片至本地

支付标记

首页双标签（未付/已付）列表

点击未付项弹窗显示收款码图片，提供“标记已付”按钮

已付列表显示支付时间

历史查账

按日期切换查看记录

按工人姓名筛选

显示汇总小计

支持删除单条记录

数据导出

生成CSV文件，通过系统分享发送至微信/文件传输助手

提供“清空所有数据”危险操作（二次确认）

四、交互流程详述（分页面）

4.1 首页（主工作台）

顶部区域：

显示当前日期（格式：2026年6月29日 星期一），字体28sp加粗居中

右上角齿轮图标，点击进入“查账页”

中央扫码区：

巨大蓝色按钮（宽85%，高120dp）："📷 扫码登记工人"

点击后调用ZXing扫码界面

扫码成功后的流程：

获取二维码内容（作为worker_id）
截取当前帧Bitmap，压缩至80%质量，保存至 /data/data/包名/files/qrcodes/{worker_id}.jpg
弹出底部半屏弹窗（BottomSheet）：
提示“已识别收款码”
工人姓名输入框（若worker_id已存在则自动填充，否则留空）
今日工资输入框（数字键盘，默认焦点）
确认按钮 "✅ 登记"（蓝色大按钮）
取消按钮（灰色小字）
点击确认：
将工人信息（id, name, qrcode_path, first_work_date）存入工人表（若已存在则仅更新name）
插入一条工资记录（work_date=今日, wage=输入值, is_paid=0）
刷新底部未付列表，Toast提示“已登记：XXX 280元”
扫码按钮正下方：灰色小字链接 "✏️ 扫码失败？点此手动录入"

点击后直接弹出同样的BottomSheet，但不填写worker_id，姓名输入框为空

确认后，worker_id生成规则：manual_ + 当前时间戳（如 manual_1719657600000）

不保存收款码图片，后续弹窗显示“无收款码图片，请手动转账”

统计汇总栏（固定于扫码区下方）：

三行，字体24sp加粗：

"💰 今日合计：0 元"

"🔴 未付：0 人"（红色）

"🟢 已付：0 人"（绿色）

每次登记或标记后自动更新

底部双标签列表：

标签栏：两个按钮并排

左：“未付（X）”，选中时红色背景（#F44336），未选中灰色

右：“已付（X）”，选中时绿色背景（#4CAF50），未选中灰色

默认选中“未付”

未付列表（RecyclerView）：

每个item卡片：左侧显示 "👤 姓名 金额XX元"；右侧绿色按钮 "✅ 标记已付"

点击“标记已付” → 弹出确认对话框“确认已向 张三 转账 280 元？” → 确认后该记录is_paid=1，记录当前时间为paid_time，刷新列表，该记录移至已付列表

已付列表：

每个item卡片：左侧 "👤 姓名 金额XX元"；右侧显示支付时间（如 14:30）

长按item → 弹出删除确认对话框 → 确认后删除该条工资记录（不影响工人信息）

空列表提示文字（区分未付/已付）

4.2 查账页（右上角齿轮进入）

顶部导航：

左侧返回箭头，回到首页

中间标题 "📊 工资记录"

筛选区域：

日期切换：两个大按钮 "← 前一天" 和 "后一天 →"，中间显示当前选中日期（默认今日）

工人筛选：下拉选择器（Spinner），默认“全部工人”，选项来自所有已登记工人姓名

汇总小计：

显示当前筛选条件下的统计："共 X 条记录，合计工资 XXXX 元，其中未付 X 条，已付 X 条"

灰色背景，字体20sp

记录列表：

每个item卡片显示：姓名、金额、日期、状态（未付/已付）、支付时间（若有）

点击无操作，长按弹出删除确认对话框

底部操作栏：

"📤 导出CSV" 按钮

生成当前筛选条件下的所有记录，文件命名 工资记录_YYYY-MM-DD.csv

调用系统分享（Intent.ACTION_SEND），可选择微信发送

"🗑️ 清空所有数据" 按钮（红色文字）

点击后弹出两次确认对话框，确认后仅删除工资记录表（保留工人信息）

五、技术选型

开发语言 ： Java
IDE ： Android Studio
本地数据库 ： Room (SQLite ORM)
扫码库 ： ZXing (com.journeyapps:zxing-android-embedded)
图片存储 ： 应用私有目录（/files/qrcodes/）无需存储权限
CSV导出 ： 手动拼接字符串 + FileProvider
最低SDK ： Android 7.0 (API 24)
网络权限 ： 无（纯本地应用）

六、数据库设计（两张表）

表1：workers（工人表）
字段名 类型 说明
id TEXT (PRIMARY KEY) 收款码内容（或手动生成的manual_前缀ID）
name TEXT 工人姓名
qrcode_path TEXT 收款码图片本地路径（可为空）
first_work_date TEXT 首次登记日期（yyyy-MM-dd）

表2：wage_records（工资记录表）
字段名 类型 说明
id INTEGER (PRIMARY KEY AUTOINCREMENT) 自增主键
worker_id TEXT 外键，关联workers.id
work_date TEXT 出工日期（yyyy-MM-dd）
wage REAL 当日工资（保留两位小数）
is_paid INTEGER 0=未付，1=已付
paid_time TEXT 支付时间（yyyy-MM-dd HH:mm），未付时为NULL
create_time TEXT 记录创建时间（yyyy-MM-dd HH:mm）

关系：worker_id 与 workers.id 为多对一关系，删除工人时应级联删除其所有工资记录。

七、非功能性需求

UI风格：大字体（≥20sp），大按钮（≥60dp），高对比度（白底黑字，红绿蓝三色）

交互反馈：所有点击需有视觉反馈（按钮颜色变化、Toast提示）

防误触：所有删除操作必须二次确认；清空所有数据需两次确认

性能：支持最多200名工人、5000条工资记录，查询响应时间<1秒

数据安全：无网络权限，所有数据仅存于手机本地，导出文件需用户手动分享

八、开发注意事项（针对补充需求）

扫码存图：

使用 Bitmap.compress(Bitmap.CompressFormat.JPEG, 80, outputStream) 压缩保存

路径构建：context.getFilesDir().getAbsolutePath() + "/qrcodes/" + worker_id + ".jpg"

无需申请存储权限（Android 7.0+ 私有目录可直接写入）

手动录入：

worker_id 生成："manual_" + System.currentTimeMillis()

不保存图片，qrcode_path 字段留空

后续弹窗显示图片时检查路径是否为空或文件不存在，若不存在则显示占位图及提示文字

图片加载失败降级：

在Adapter中加载图片时，若 BitmapFactory.decodeFile(path) 返回null，则使用默认占位图（例如 R.drawable.ic_no_image）

日期处理：

统一使用 LocalDate (API 26+) 或 SimpleDateFormat，建议使用 java.time 包（需开启coreLibraryDesugaring）

鸿蒙兼容性：

打包为APK，鸿蒙系统默认兼容

注意：华为手机可能限制后台活动，但本App不涉及后台服务，无影响
